# 发布后线上验证（第 2 轮）—— 查出一个让应用等于不可用的 P0

## 结论先说：线上原本「一生成就永远转圈」
用户确认「同步更新到线上」后发布并做线上端到端验证，**当场复现了严重问题**：填完表单点生成，页面进入加载态后**在 150 秒内没有任何完成迹象**。

## 根因：`pickModelId()` 取了模型列表第一项 = 高推理模型
- `cloudLLM.ts` 原实现 `cachedModelId = usable[0].id`。云端 `/.cloud/llm/models` 返回的**第一项是 `auto`**，它路由到 `reasoning.effort: high` 的思考模型，元数据 `onlyReasoning: true`。
- 实测（同一份完整 PLAN 提示词，3 天杭州行程，直连 `POST /.cloud/llm/chat/completions`）：

| 模型 | 首个内容分片 | 总耗时 | 结果 |
|---|---|---|---|
| `auto`（原逻辑选中） | **223.11s** | **243.59s** | JSON 可解析，但用户已当成卡死关页 |
| `deepseek-v4.1-flash`（改后选中） | **1.81s** | **13.17s** | 3 天 / 每天 3 景点 / 3 条天气 / budget 齐全 |

**18.5 倍差距。** 行程生成是结构化 JSON 输出，不需要长链思考。
- 另注：`auto` 一个「只输出一个 JSON」的极小请求就烧掉 369 个 reasoning token、耗时 6.2s。

## ⚠️ 安全发现（已上报，未擅自改线上策略）
- **匿名可写**：直接 curl 打 `POST /.cloud/database/rest/trip_plans`（不带任何会话）返回 **201 写入成功**，落库行 `owner_id = 'anon'`。
- 原因：平台对**完全没有会话**的调用方也按 `anon` 身份处理，`auth.uid()` 返回字面量字符串 `'anon'`；而策略是 `WITH CHECK (owner_id = auth.uid())` → 对 anon 恒真。即「未登录访客共用同一个 anon 租户」，可互相读写；客户端 `requireSession()` 只是 UX 门禁，**服务端没拦住**。
- 影响面：**读不到已登录用户的行程**（uid 不同），属于共享公共暂存区，不是用户私数据泄露；但任何拿到 publishableKey（前端包里公开）的人都能写。
- 另：**Origin 校验可被非浏览器客户端伪造**（curl 带 `Origin` 头即可通过），它只挡跨站浏览器请求，不是安全边界。
- 平台文档 `references/database/management.md` L129-131 明确说：`GRANT ... TO authenticated, anon` 是常规做法，**只授 `authenticated` 会让 anon 角色的会话写入报 42501（会被误当成 RLS bug）**。所以「把 anon 锁掉」这一步**有风险且无法在无邮箱会话的情况下验证**，已留给用户拍板，未动线上策略。
- 我的探测行已用 `mode: "write"` 删掉，`trip_plans` 回到 0 行。

## 云服务接口的实操细节（省下次踩坑）
- 鉴权头是 **`x-wb-webapp-access-key`**（不是 `apikey`，不是 `Authorization`）。用错会返回 `{"error":"invalid_client"}` 401。
- 路径前缀 `/.cloud`：LLM = `/.cloud/llm/chat/completions`、`/.cloud/llm/models`；数据库 = `/.cloud/database/rest/...`；auth = `/.cloud/auth`。
- **模型列表不能盲信**：`glm-4.7` 在列表里 `enabled: true`，实调却返回 `request_invalid_parameter` 400。所以「取列表第一项可用模型」这种做法本身就不成立。
- `response_format: { type: 'json_object' }` 被接受（实测 deepseek-v4.1-flash 正常返回）。
- 模型元数据里 `credits` 是形如 `"x0.11 credits"` 的字符串，取值要正则抠数字。

## 15:10 「图片还是没显示」深挖：不是图片的问题，是窄屏把容器压扁了

### 排查过程（先证伪，再定位）
- 先怀疑图片本身：线上 1440px 全页滚动后审计 **19 张图，0 张 `naturalWidth === 0`**，
  桌面/窄屏两档都全部解码成功 → **图片链路是好的，用户看到的不是"加载失败"**。
- 再怀疑高德 InfoWindow（以为里面有图）→ 查代码 `buildInfoWindowContent` 只输出文本，无图。
- 也确认了插画生成器 `attractionArtwork.ts` **不依赖景点名的字符**（种子只用于取色/选场景），
  不存在"某个城市名导致 src 为空"的情况。
- 于是做**宽度扫描**（本地假数据，免费）：`.workbuddy/scripts/probe-width-sweep.js`（新）——
  断崖出现在 ≤640px：每日行程卡被压到 96px 宽、**卡里的图只剩 70px 一条**，
  正文一行一个字。**图片解码是成功的，但容器只剩 70px，用户体感就是"图没加载"。**

### 根因与修法
- 根因：`<a-list :grid="{ gutter: 16, column: 2 }">` —— Ant Design Vue 的 List grid 把列宽写成
  **内联 style**（`width: 100/column %`），窄屏不会自己收敛，两列在手机上各占 96px。
- 修法（`Result.vue`）：`:grid="{ gutter: 16, column: 2, xs: 1, sm: 1, md: 2, lg: 2, xl: 2, xxl: 2 }"`。
  **断点必须写在 `grid` 顶层**——源码 `es/list/index.js` 是 `props.grid[currentBreakpoint] ?? props.grid.column`，
  写成 `column: { xs: 1 }` 嵌套无效（会掉回 column 拿到对象 → 列宽 NaN）。
- 顺带修窄屏第二处：预算明细是固定列表格，390px 下把整张卡撑破（卡 654px 挤在 340px 容器，
  右侧 ITEM 列被裁掉）→ `@media (max-width:768px)` 里给 `.budget-card` 加 `min-width:0; max-width:100%; overflow-x:auto`。
- 修后扫描：1440→579px / 768→259px / 640→480px（单列）/ 390→**230px**（单列），
  预算卡 390px 回到 340px（横向滚动不再裁切）。桌面尺寸完全未变。
